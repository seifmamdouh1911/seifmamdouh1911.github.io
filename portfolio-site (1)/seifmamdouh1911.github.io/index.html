Project · AI chatbot

Iron Nile Gym Assistant

A bilingual chatbot for gyms. It answers members in Arabic or English, captures new leads, and passes anything that needs a person to the manager.

View on GitHub →

Problem

A gym's inbox fills up with the same questions: how much is a membership, when are the classes, where is the gym. Members ask in Arabic and English, at any hour. Someone ready to join leaves a phone number in the middle of a chat and it gets lost, and a member who needs a person is buried under everything else. Slow replies mean lost members.

Solution

  • Repeat questions are answered instantly.It gives prices, class times and the gym's location in Arabic or English, matching the member's language, so staff stop typing the same replies.
  • No lead gets lost.When someone wants to join, it collects their name, goal and phone number and puts them on the manager desk, ready to contact.
  • The manager sees only what needs them.Every message gets a category (question, lead, freeze request, complaint, refund or other), and anything that needs a person, such as a complaint or refund, goes to a "Needs your reply" list.

Detail

The assistant answers in the customer's own language and dialect (Egyptian Arabic, Arabic or English), so both can appear in the same conversation. Quick-reply suggestions help new visitors start, and the manager desk becomes a drawer on small screens.

How it works

A Flask server exposes one chat endpoint. The gym's information and the rules for the assistant go to Google's Gemini model as a system prompt, and the model must answer in JSON: the reply for the customer, a category, a flag for whether a person is needed, and any lead details shared so far (name, goal and phone).

The page shows the reply in the chat and updates the manager desk from the same response. Each request includes the last 12 messages, so the assistant keeps the context of the conversation. It answers only from the gym information it is given, and says the manager will get back to the customer when the answer isn't there.

Challenge

Language models don't always return clean output, and a lost lead means a lost member. So the server checks every response and does not trust it blindly:

  • Validated output.Every field the page needs is filled in, and JSON is parsed even when the model wraps it in extra text.
  • Retry and fallback.A failed request is retried once. If both attempts fail, the customer still gets a polite reply and the request is passed to the manager.
  • A safety net for phone numbers.A pattern for Egyptian mobile numbers, including Arabic-Indic digits, catches the number even if the model misses it.

Stack

Python, Flask, Google Gemini API (google-genai), HTML, CSS and JavaScript. The API key is read from an environment variable and is not stored in the code. Messages over 1,000 characters are rejected.

Iron Nile Gym is a demo gym. Its hours, prices and classes are sample data that a real gym would replace with its own.

NTI graduation project · Team of four

Human Activity Recognition Using Smartphones

A machine learning model that tells what a person is doing (walking, going up or down stairs, sitting, standing or laying) from a phone's motion sensors alone, with 95.42% accuracy on volunteers it had never seen.

30volunteers, ages 19 to 48
6activities recognized
561engineered sensor features
5models compared
95.42%test accuracy, final model

Problem

Fitness apps, elder-care services and health researchers want to know what a person is doing right now: exercising, sitting for hours, or lying down when they shouldn't be. Cameras, extra wearables and manual observation are hard to scale.

Solution

  • It uses the phone people already carry.It reads the accelerometer and gyroscope from a waist-mounted phone, so no extra wearable or camera is needed.
  • It works on new people.It was trained on 21 volunteers and tested on 9 different ones, so the accuracy reflects people the model has never seen, not memorized rows.
  • It is light and cheap to run.The winner was a tuned Logistic Regression, a classical model, so it needs no deep learning or heavy compute.

Who could use it: fitness and wellness apps, elder-care monitoring services, and health insurers and researchers. I also wrote a business model canvas that frames it as a licensable activity-recognition service.

The model separates laying from every other activity almost perfectly. The hardest pair is sitting and standing: 58 sitting windows were predicted as standing and 20 the other way, because both are still, upright postures. Random Forest feature importance showed gravity orientation and motion energy as the most predictive signals, and PCA showed two components already separate still activities from moving ones.

Method

  1. Data validation. Shape, data types, nulls, duplicates, outliers.
  2. Exploratory analysis. Class balance, distributions, correlations.
  3. Preprocessing. Scaler fit on training data only, so nothing leaks from the test set.
  4. Model training. Five classifiers compared on accuracy and macro F1.
  5. PCA and feature importance. Which signals matter most.
  6. Tuning and final test. GridSearchCV, then one clean evaluation.

Dashboard

I turned the trained model into a Streamlit app with seven pages: project description, dataset, activity distribution, model comparison, confusion matrix, PCA, and a live prediction demo.

In the demo you pick a real row from the test set. The app scales it with the same scaler used in training, predicts the activity with the tuned model, and shows the true label against the prediction, the class probabilities and the raw feature values. It loads the saved model, so it needs no retraining.

Stack

Python, scikit-learn, PCA, GridSearchCV, Streamlit. Dataset: UCI Human Activity Recognition Using Smartphones.

Project · Full-stack web app

LevelUp

A gamified personal growth app. Users turn real-life goals into tasks, earn XP in categories like Study, Fitness and Health, level up, and compare progress on a leaderboard.

View on GitHub →

Problem

To-do lists are easy to start and easy to abandon. There is no sense of progress, so people lose motivation to keep up habits like studying, exercising or saving money.

Solution

  • Every task is worth XP.Users add a task, choose a category and an XP value. Completing it adds the XP to that category.
  • Progress you can see.Each 300 XP is a new level, overall and per category, with progress bars, a 7-day activity chart and a monthly summary.
  • A bit of competition.A leaderboard ranks users by total XP, and profiles show skill progress and recent activity.

Features

  • Accounts. Register and log in, with passwords hashed.
  • Task board. In-progress and completed tasks with XP rewards.
  • Categories. Six defaults plus custom categories, each with its own level.
  • Dashboard and summary. Charts for daily activity, XP history and category trends.
  • Leaderboard and profiles. Ranking by total XP, with editable profiles.
  • Admin panel. User list, task distribution, sign-up trends and a live activity log.

Screens

How it works

The back end is PHP with PDO and prepared statements over a MySQL database with five related tables: users, categories, user categories (XP and level per user), tasks, and a task history log. Users have a user or admin role, and pages check the session before loading.

The front end uses Tailwind CSS, JavaScript for the task modals and updates, and Chart.js for the dashboard, summary and admin charts.

Stack

PHP, MySQL (PDO), JavaScript, Tailwind CSS, Chart.js, HTML and CSS.
